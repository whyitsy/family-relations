# 地区称谓（方言）自定义方案

> 目标：解决「亲戚关系在不同地区叫法不同」的问题——称谓不再写死，而是可修改、可添加，并可按地区/方言预设切换。
> 状态：**已实现**。第 2 节基础改造、第 3 节内置预设（普通话 + 粤语）、第 4 节自定义规则集与编辑界面（修改称谓、添加/删除规则、关系路径组合器）均已落地；更多方言预设（四川话、吴语等）可按需继续追加。

---

## 1. 背景与目标

现状：称谓规则写死在 `KinshipRuleBook`（静态数组），全部为普通话常见称谓（爸爸/妈妈/爷爷/外婆/伯父/堂兄…）。不同地区（粤语、四川话、吴语、客家话、闽南语等）叫法差异大，用户无法按本地习惯使用。

目标：

1. **可修改**：把某条规则的称谓文本改成本地叫法（如「爸爸」→「老豆」）。
2. **可添加**：新增现有规则库未覆盖的关系（含长幼/性别/路径组合）。
3. **可按地区切换**：内置多套方言预设，一键切换当前图谱的称谓风格。
4. **自定义可持久化**：用户改动的规则随文档保存，不因升级丢失。

约束（与现有工程一致）：

- Native AOT 安全：规则为纯数据 + 源生成器 JSON，禁用反射、动态编译、动态 XAML。
- 规则必须可序列化（`System.Text.Json` 源生成器上下文）。
- 每个图谱可独立选择规则集（多图谱功能已引入 `FamilyGraph.RuleSetId`）。

## 2. 数据模型与基础改造（已完成 ✅）

### 2.1 规则集数据化

- 新增 `KinshipCalculator.Core/Rules/KinshipRuleSet.cs`：
  ```csharp
  public sealed class KinshipRuleSet
  {
      public string Id { get; set; }   // "mandarin" / "cantonese" / 自定义 GUID
      public string Name { get; set; } // "普通话" / "粤语" / "我的自定义"
      public List<KinshipRule> Rules { get; set; } = new();
  }
  ```
- `KinshipRule`（原已存在，为纯数据 record）：`Id / Pattern(StepKind[]) / SelfGender / TargetGender / AgeRule / AgeStepIndex / TermIfOlder / TermIfYounger / Term`。
- 原 `KinshipRuleBook` 重构为 `BuiltInRuleSets`，提供内置预设（当前仅「普通话」）：
  ```csharp
  public static class BuiltInRuleSets
  {
      public const string MandarinId = "mandarin";
      public static KinshipRuleSet Mandarin { get; }
      public static IReadOnlyList<KinshipRuleSet> All { get; }       // 内置预设
      public static IReadOnlyList<KinshipRule> RulesFor(string? id); // 未知 Id 回落普通话
  }
  ```

### 2.2 计算器按规则集计算

- `RelationshipCalculator.ComputeAll(FamilyData data, IReadOnlyList<KinshipRule>? rules = null)`：
  传入空时默认普通话，调用方传入规则集即可切换称谓。

### 2.3 图谱绑定规则集

- `FamilyGraph` 新增 `RuleSetId`（默认 `"mandarin"`）。
- 主视图模型 `Recalculate()` 按 `CurrentGraph.RuleSetId` 解析规则集后计算。

### 2.4 序列化

- `FamilyDataJsonContext` 已注册 `KinshipRuleSet / KinshipRule / List<KinshipRule> / StepKind[]`。
- 规则集随文档序列化（AOT 源生成器），单元测试已覆盖往返。

## 3. 内置方言预设（待实现）

做法：为每种方言新建一个 `KinshipRuleSet`，`Pattern` 与普通话**完全相同**，只改称谓文本（含 `Term`、`TermIfOlder`、`TermIfYounger`）。因为规则结构一致，只需准备「称谓映射表」即可生成预设。

建议首批预设（优先级由用户确认）：

| Id | 名称 | 说明 |
|----|------|------|
| `mandarin` | 普通话 | 现有规则（已完成） |
| `cantonese` | 粤语（广州话） | 老豆/老母/爷爷/嫲嫲/公公/婆婆/伯父/叔父/姑姐/舅父/姨妈/堂哥… |
| `sichuan` | 四川话 | 老汉儿/妈/爷爷/婆婆/外公/外婆/大伯/幺叔/嬢嬢/舅舅/舅妈… |

> 注：方言的亲属称谓边界（如「伯/叔」「堂/表」细分程度）各地方言差异大，预设尽量采用该方言最通用、无歧义的说法；无法一一覆盖的，保留普通话兜底。

数据来源：内置预设的称谓表由需求方提供或经方言资料核对后录入（每条规则对应一个术语表行，纯数据、无逻辑改动）。

## 4. 自定义规则集与编辑界面（待实现）

### 4.1 规则集归属

- 文档级新增 `KinshipDocument.RuleSets`（`List<KinshipRuleSet>`），存放用户自定义规则集；内置预设不入库。
- 解析顺序：内置预设 → 文档自定义集 → 回落普通话。
- `FamilyGraph.RuleSetId` 可指向任意内置或自定义集。

### 4.2 「称谓规则」管理界面

新增一个窗口/面板（类似已移除的「光学发送」窗口，从工具栏按钮进入），包含：

1. **预设选择**：下拉列出「内置预设 + 我的自定义集」；选中即切换当前图谱的 `RuleSetId`。
2. **规则列表**：每行展示：
   - 关系路径（人类可读，如「父亲的兄弟」）
   - 目标性别 / 长幼规则
   - 当前称谓文本（可编辑）
   - 长幼两个变体文本（older / younger，可编辑）
3. **新建自定义集**：以某预设为模板复制一份，之后所有编辑都落在自定义集上（内置预设保持只读）。
4. **修改称谓**：直接编辑文本，即时保存、重算当前图谱称谓。
5. **添加规则**：见 4.3。
6. **删除规则**：从自定义集中移除（内置预设不可删）。

### 4.3 添加规则的「关系路径」组合器

新增规则的本质是「路径模式 + 约束 + 称谓」：

- **路径模式**：由若干「步」组成，每步从 `父 / 母 / 儿子 / 女儿 / 配偶 / 兄弟 / 姐妹 / 孩子(未知) / 兄弟姐妹(未知)` 中选择。UI 用一排按钮「+父亲 +母亲 +儿子 +女儿 +配偶 +兄弟 +姐妹…」逐级追加，实时预览人类可读路径（如「我的父亲的兄弟」）。
- **约束**：目标性别（男/女/不限）、我的性别（男/女/不限）、长幼比较（不比较 / 与我比 / 与上一步比）。
- **称谓**：主称谓 + （可选）年长称谓 + 年幼称谓。

生成的 `KinshipRule` 追加到当前自定义集，立即生效。

### 4.4 编辑模型与实现要点

- 编辑对象是 `KinshipRuleSet` 的**深拷贝**，避免改到内置单例；保存时写回 `_document.RuleSets` 并持久化。
- 规则列表用 `ObservableCollection<KinshipRule>` + 编译绑定展示（`KinshipRule` 可改为带 `INotifyPropertyChanged` 的类，或列表行用只读展示模型 + 文本双向绑定，避免 record 可变性隐患——实现时二选一）。
- 所有操作为纯数据操作，无反射、无动态编译，AOT 安全。

## 5. 兼容性与迁移

- 现有 `data.json`（单 `FamilyData`）已在多图谱改造中自动迁移为 `KinshipDocument`（含 1 个 `RuleSetId="mandarin"` 的图谱），**无需用户操作**。
- 新增 `KinshipDocument.RuleSets` 字段后，旧文档反序列化该字段为 null → 规范化为空列表，向后兼容。
- 单图谱「导出/导入 JSON 文件」「复制/粘贴」仍走 `FamilyData` 格式，与规则集无关（规则集只影响计算结果显示，不改变家谱数据结构本身）。多图谱整体导入/导出走 `KinshipDocument`。

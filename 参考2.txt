# 一、总体目标
构建一个以“我”为中心的人物关系图，用户录入人物及基础关系后，系统自动计算图中所有其他人与“我”的亲戚称谓，并以图形化方式展示（树形或网状结构）。称谓需符合中国常见的亲属称呼习惯。

# 二、数据模型
1. Person（人物节点）：
   - id：唯一标识
   - name：姓名
   - sex：性别（男/女）
   - birthDate：出生日期（用于判断年龄长幼）
   - 其他可选：备注

2. Relation（关系边）：
   - FATHER：父亲（指向该人的父亲）
   - MOTHER：母亲
   - SPOUSE：配偶（双向，指向配偶）
   - SIBLING：兄弟姐妹（需标注是“同父同母”“同父异母”“同母异父”）
   - 说明：子女关系可由 FATHER/MOTHER 反向推导，可不显式存储。
# 三、称谓计算规则
核心思路：将“我”到目标人物的路径（由基础关系组成）匹配规则库，得到称谓。

基础关系符号：
- F：父亲
- M：母亲
- S：配偶
- B：哥哥/弟弟（需根据年龄判断长幼，可细分为 B_older / B_younger）
- Z：姐姐/妹妹（同样区分长幼）

| 路径模式 | 条件 | 称谓 |
|---------|------|------|
| [F] | 目标为男 | 爸爸 |
| [F] | 目标为女 | 妈妈 |
| [F, F] | 目标为男 | 爷爷 |
| [F, F] | 目标为女 | 奶奶 |
| [M, F] | 目标为男 | 外公 |
| [M, M] | 目标为女 | 外婆 |

注意：
- 路径中的 SIBLING 需区分长幼和性别，否则无法准确判断“伯/叔/姑/舅/姨”和“堂/表”。
- 称谓可能依赖“我”的性别（如姻亲关系）。
- 对于平辈，需要根据年龄判断“兄/弟/姐/妹”。
- 若存在多条路径（例如近亲结婚导致），应优先选择最短路径，并提示可能存在多重关系。

# 四、算法流程
1. 用户录入人物节点和关系边，指定“我”是哪个节点。
2. 遍历图中除“我”之外的所有节点。
3. 对每个目标节点，使用深度优先搜索（DFS）或广度优先搜索（BFS）找出“我”到目标节点的所有简单路径（限制最大深度为 8，因更远亲属称谓已很少使用）。
4. 将每条路径转换为由基础关系组成的模式（如 [F, B_older]）。
5. 结合以下信息进行规则匹配：
   - 路径模式；
   - “我”的性别；
   - 目标节点的性别；
   - 路径中涉及的兄弟姐妹与目标节点的年龄比较（用于判断长幼）。
6. 匹配规则库，得到称谓。若多个路径匹配多个称谓，选择路径最短的；若仍冲突，返回多个候选并提示。
7. 输出所有节点的称谓列表，并支持图形化展示。

# 五、补充说明
- 如果遇到规则库未覆盖的路径，应返回“未知关系”或提示“关系较远，暂无标准称谓”。
- 请确保算法能正确处理同父异母/同母异父的兄弟姐妹（可简化为 SIBLING 并忽略差异）。
- 请将核心规则引擎设计为可扩展，方便后续添加更多称谓规则。
